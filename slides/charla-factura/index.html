🔤 ACTO 3 — Tokens

Los modelos no leen texto como tú

"Hola mundo ¿cómo estás?"

Ho la mun do ¿ cómo estás ?

Mientras más tokens envías… más pagas.

📥 Pagas por lo que ENTRA 📤 Pagas por lo que SALE

Tres tipos de tokens. Tres precios.

📥
INPUT TOKENS
Lo que tú mandas al modelo.
System prompt + historial + pregunta del usuario.
📤
OUTPUT TOKENS
Lo que el modelo responde.
Más costoso por token que el input en la mayoría de proveedores.
♻️
CACHED TOKENS
Contexto reutilizado por el proveedor.
Hasta 90% más barato. El oro oculto del costo.
"El mismo prompt puede costar diferente según el proveedor — y según el modelo."

⚙️ ACTO 5 — Ingeniería de Costo

La IA también requiere OPTIMIZACIÓN.

Prompt Engineering desde ingeniería, no desde humo.

🎯
Claridad
Elimina ambigüedad. Un prompt claro genera tokens de calidad, no tokens de ruido.
🗜️
Compresión
Solo el contexto necesario. Sin repeticiones, sin datos irrelevantes, sin padding.
🏗️
Estructura
Formato eficiente. XML para estructura (Claude lo tokeniza mejor), Markdown para listas y contexto. JSON conciso, instrucciones directas sin relleno.
♻️
Reutilización
Cached tokens. El system prompt estático debería estar en caché siempre.

Los errores que queman dinero

🗃️
Historial completo innecesario
Mandas toda la conversación cada vez. 40 mensajes de historial = 40× el costo base.
📦
JSON gigantes como contexto
Payloads enormes con campos irrelevantes. Solo manda lo que el modelo realmente necesita.
🖼️
Imágenes Base64 enormes
Imágenes en texto plano al modelo. Una foto de 2MB = miles de tokens de imagen.
📜
System prompts kilométricos
Instrucciones redundantes, ejemplos repetidos, reglas que ya son el default del modelo.
🔍
RAG mal optimizado
20 documentos recuperados, chunks enormes, embeddings inútiles. Contexto que no aporta nada.

"Cada uno de estos errores multiplica tu factura."

Optimizaciones que marcan la diferencia

🗄️
Caching
Semantic caching, prompt caching y response caching.
Hasta 90% de reducción en tokens repetidos.
System prompts estáticos → siempre en caché
🤏
Small Language Models
Para tareas simples, modelos pequeños = costo mínimo.
